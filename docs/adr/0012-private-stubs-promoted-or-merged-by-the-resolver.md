# User-created assets start private; only the resolver makes them shared

An import or manual entry creates an asset owned by that user (`assets.owner_user_id`). Shared assets can only be written in "system mode" (a flag set by the resolver job, Operator routes and the security MCP server, never by a user request), so one user can never rename, delete or poison an asset others price from. When the resolver verifies a stub it either promotes it in place (owner becomes NULL) or, if the same security is already shared, merges it into that twin by repointing the owner's holdings, transactions and quant runs and deleting the stub. Considered: one global namespace with only application-level checks (a missed check lets one user corrupt everyone's data) and per-user copies of every asset (multiplies market-data fetches by users, defeating shared Reference data). Consequence: the resolver now runs each asset as its owner, because the resolution context reads the owner's private transactions.
